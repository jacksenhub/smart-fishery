# MAKER-ESP32-PRO 四路舵机与 SXTL 推杆控制板 02

这个目录用于第二块 MAKER-ESP32-PRO 控制板，同时控制四路舵机和一根 12V SXTL 推杆。

## 烧录文件

```text
maker_esp32_pro_four_servo_02.ino
```

设备 ID：

```text
舵机：servo-quad-02
SXTL：maker-esp32-pro-linear-01-m1
```

两块开发板的舵机接口引脚完全相同，但通过不同设备 ID 区分：

```text
第一块板：servo-quad-01
第二块板：servo-quad-02
```

## 舵机接口

```text
Servo 1 -> GPIO25
Servo 2 -> GPIO26（水枪开关，67° 开启，即从竖直方向转动 23° / 90° 关闭并返回竖直）
Servo 3 -> GPIO32
Servo 4 -> GPIO33
```

在网页中，第二块板对应整体舵机编号：

```text
舵机 4-7
```

## 12V SXTL 推杆接线

```text
SXTL 两根动力线 -> M0 电机输出口
M0 控制引脚     -> GPIO27 / GPIO13
```

SXTL 由 M0 板载 H 桥反转电源极性：

- 正功率：伸出。
- 负功率：缩回。
- 零功率：停止。

固件允许 M0 输出到 100%，同时保留缓启动、WiFi 断开停止、急停和 2.2 秒命令超时保护。

SXTL 必须使用内置端点限位。正常操作时，第一段伸出（或缩回）到端点后点击“停止”，再完成相反方向并再次点击“停止”，记为 1 次完整往返。固件采用双重保护：累计完成 4 次往返，或累计指令运行达到 2 分钟，任一条件先满足都会停止输出并冷却 18 分钟；冷却结束后次数和时间同时清零。

内置端点限位只能切断推杆本体电流，ESP32 没有位置或电流传感器，无法自行知道推杆已经到端点。因此每次到端点后必须点击网页“停止”，否则固件仍会继续累计命令运行时间。

## 后端接口

```text
GET  /api/device/commands?device_id=servo-quad-02
POST /api/servos/status
GET  /api/propulsion/commands?device_id=maker-esp32-pro-linear-01-m1
POST /api/propulsion/status
```

## 使用前确认

1. 电脑后端保持运行，端口为 `5000`。
2. 第二块板和电脑连接同一个 WiFi。
3. 确认 Windows 防火墙允许 TCP 5000 和 UDP 42110；固件会自动发现电脑后端，不需要写死 WLAN IPv4。
4. 舵机使用外部稳定供电，不建议只靠 USB。
5. SXTL 使用 12V 动力电源，不能由 USB 供电。
6. 板载单电机标称最高 3A，而 SXTL 正常约 2A 且启动电流更高；第一次只能空载短时测试，并确保可以立即断电。

## 网页安全状态反馈

第二块开发板会通过 `/api/propulsion/status` 上报 SXTL 的安全锁定、往返阶段、完整往返次数、累计指令运行时间、剩余工作额度和冷却时间。网页显示“第一段完成，可以立即反向”时，可以直接开始相反方向；达到 4 次往返或 2 分钟累计时间后显示 18 分钟冷却倒计时。网页出现“等待点击停止”时，先点击中间的“停止”按钮解除安全锁定。
