# 比赛演示运行手册

## 演示前一天

1. 固定比赛用电脑、2.4GHz 热点名称和密码，不再临时换网络。
2. 运行 `npm install`、`npm run firmware:setup`、`npm run firmware:check`。
3. 运行 `npm run setup:devices`。默认保留现有令牌；不要运行 `setup:devices:rotate`。
4. 若热点信息有变化，重新烧录实际使用的全部 ESP32。
5. 启动项目后运行 `npm run doctor`，确认参赛设备在线。
6. 空载测试舵机四个方向、归中、急停和电机零输出，再连接机械负载。

## 上场前 15 分钟

1. 关闭所有旧终端，只保留一个项目终端。
2. 确认热点为 2.4GHz，电脑和开发板均已连接，关闭手机热点自动休眠。
3. 运行 `npm run dev`，打开 `http://localhost:3000`。
4. 另开一个终端运行 `npm run doctor`。
5. 确认第一块板 `servo-quad-01` 在线，所有要展示的执行机构处于停止状态。
6. 检查独立舵机电源、共地、接头、机械限位，移开螺旋桨和推杆危险区域内人员。

## 快速故障恢复

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| `EADDRINUSE` 或网页跳到 3001 | 旧进程占用端口 | 在旧终端按 `Ctrl+C`，确认 3000/5000/42110 释放后只启动一次 |
| 开发板有热点 IP但网页离线 | 令牌不同或旧固件 | 运行 `npm run doctor`；同步配置后重新烧录对应 ESP32 |
| 串口出现 HTTP 401 | 固件令牌与后端不同 | 运行 `npm run setup:devices` 并重新烧录 |
| 串口出现发现后端超时 | UDP、防火墙或热点隔离 | 运行 `npm run setup:network`，确认同一热点且未启用客户端隔离 |
| 舵机轻微抖动 | 供电、共地、机械负载或脉宽 | 单路空载测试，改用独立稳定电源并共地，检查限位 |
| GPS 串口离线 | GPS 供电/接线问题 | 检查 5V、GND、GPS TX 到 GPIO33；移到室外等待定位 |
| 网页方向与实物相反 | 安装方向校准不一致 | 停止自动跟踪，先手动验证四向映射，再启用识别跟踪 |

演示过程中不要更新依赖、轮换令牌、修改热点或重新安装驱动。若 AI 网络不可用，系统会使用本地预测逻辑，不影响基础演示。
