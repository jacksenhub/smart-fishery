# 构建验证与版本记录

本文记录项目当前的构建状态、主要验证范围和发布前检查项。

## 构建与自动化检查

- CI 通过 ESLint、后端单元测试、TypeScript 类型检查和生产构建。
- 项目使用 Node.js 22.20 及以上版本，依赖版本由 `package-lock.json` 锁定。
- ESP32 固件使用 Arduino Core `3.3.11`。
- ESP32Servo `3.2.1`、TinyGPSPlus `1.0.3` 和 Simple FOC `2.4.0` 已纳入固件构建检查。
- 第一控制板、第二控制板、GPS 和 SimpleFOC 四套固件均通过编译。

本地验证命令：

```powershell
npm run lint
npm test
npm run typecheck
npm run build
npm run firmware:check
```

## 设备通信与状态管理

- 设备仅提交满足范围要求的数据，舵机和推进器命令在写入队列前进行校验。
- 设备离线时拒绝新的运动命令，急停命令仍可下发。
- 设备状态包含时间戳，陈旧数据不会继续显示为在线状态。
- 后端以短有效期命令队列支持设备轮询，并避免同一命令重复执行。
- ESP32 和局域网控制接口使用设备控制令牌校验。

## 数据来源与可用性

- 水质、电池和导航数据均携带来源字段。
- 演示数据与实时数据分区处理，不覆盖真实历史。
- 后端连接断开时，前端显示离线状态，不沿用旧值伪装为实时数据。
- 地图瓦片不可用时使用本地离线底图。

## 固件安全逻辑

- 舵机目标角度按硬件范围进行限幅。
- 电机和推杆上电默认停止，只有有效网页命令允许输出。
- 网络或后端失联时停止全部电机输出。
- 电机命令在超过 2.2 秒未刷新后停止。
- 推杆具备运行时长、往返次数和冷却保护。
- SimpleFOC 固件默认关闭电机输出，启用前必须完成电机参数和接线确认。

## 发布前检查

1. 使用本机配置文件填写 Wi-Fi、设备控制令牌和第三方 API 密钥。
2. 确认配置文件和构建产物未进入版本库。
3. 运行 Web、后端与桌面端测试。
4. 编译实际使用的全部 ESP32 固件并重新烧录。
5. 在断开机械负载的条件下测试舵机、电机和推杆。
6. 在真实船体上复测急停、限位、断网恢复和推杆冷却保护。
7. 确认水质数据来源、GPS 定位状态和 AI 分析结果未被误标为实测。

## 已知边界

- 电动推杆没有位置和电流传感器，运行保护依据命令时长与操作顺序，不代替机械限位。
- SimpleFOC 板的电机型号、极对数、供电和编码器参数需按实际硬件确认。
- 水质传感器未接入时，页面使用明确标记的演示或占位数据。
