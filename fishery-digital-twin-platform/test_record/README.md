# Test Records

本目录保存设备固件联调过程中捕获的串口日志，用于核验设备通信状态和异常行为。

## 记录原则

- 每份日志必须来自实际运行，并注明测试条件。
- 原始日志只删除密码、设备令牌和个人信息，不改写运行结果。
- 没有实际捕获到的测试不创建占位文件。
- 日志说明与固件版本、硬件连接和测试范围保持一致。

## 日志解读边界

- `POST /api/.../status -> 201` 表示后端已接受状态上报。
- `M0=0%`、`M1=0%`、`M2=0%` 是固件上报的输出状态，不是电机电流或机械位置反馈。
- `Status [90, 90, 90, 90]` 中前三个值是第一块板三路舵机的控制角度；第四个值是接口兼容字段，不对应物理舵机。
- 未连接 GPS 时出现 `serial=offline, bytes=0` 是预期结果。
- 单块控制板可以通过多个逻辑设备 ID 上报舵机、电机和 GPS 状态，但这不等同于多板同时在线验证。

## 基线日志可以证明什么

- ESP32 能够启动并初始化固件；
- ESP32 已连接 Wi-Fi 和后端；
- 设备控制令牌校验通过；
- 舵机、M0、M1/M2 和 GPS 状态能够按不同周期上报；
- 后端能够按不同设备 ID 接收状态。

## 基线日志不能证明什么

- 不能证明后端下发的控制命令被正确执行；
- 不能证明舵机、电机或推杆产生了实际机械动作；
- 不能证明 GPS 定位正常；
- 不能证明断网停机和急停保护有效；
- 不能证明固件采用非阻塞架构。当前实现是周期性轮询，其中网络请求和部分初始化流程仍包含同步等待。

控制执行和故障保护需要分别补充实际运行日志后，才能作为对应功能的验证证据。
