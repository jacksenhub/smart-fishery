## 4. T01 空载基线测试

### 4.1 测试目的

- 验证 ESP32 能够正常启动；
- 验证设备能够连接 Wi-Fi 和后端；
- 验证不同逻辑设备 ID 能够分别上报状态；
- 验证 GPS 未连接时能够显示离线状态。

### 4.2 测试条件

- 未连接电机、推杆和外部舵机；
- 未连接 GPS；
- ESP32 仅通过 USB 供电；
- Wi-Fi 和后端连接正常；
- 后端与固件使用一致的控制令牌。

### 4.3 串口原始日志

```text
19:31:27.117 -> maker-esp32-pro-dc-01 M0=0%, POST /api/propulsion/status -> 201
19:31:27.384 -> Status [90, 90, 90, 90], POST /api/servos/status -> 201
19:31:27.853 -> maker-esp32-pro-linear-02 M1=0%, M2=0%, POST /api/propulsion/status -> 201
19:31:28.520 -> [GPS] serial=offline, bytes=0, chars=0, fix=waiting, check 5V/GND/GPS-TX->GPIO33
19:31:28.661 -> POST /api/gps/status -> 201
19:31:28.973 -> maker-esp32-pro-dc-01 M0=0%, POST /api/propulsion/status -> 201
19:31:29.486 -> Status [90, 90, 90, 90], POST /api/servos/status -> 201
19:31:29.721 -> maker-esp32-pro-linear-02 M1=0%, M2=0%, POST /api/propulsion/status -> 201
19:31:30.365 -> maker-esp32-pro-dc-01 M0=0%, POST /api/propulsion/status -> 201
19:31:30.494 -> [GPS] serial=offline, bytes=0, chars=0, fix=waiting, check 5V/GND/GPS-TX->GPIO33
```

### 4.4 结果判定

- 舵机状态上报返回 HTTP `201`；
- M0 状态上报返回 HTTP `201`；
- M1/M2 状态上报返回 HTTP `201`；
- GPS 状态上报返回 HTTP `201`；
- 多项状态按照不同周期交错输出；
- 未连接 GPS 时正确报告 `serial=offline, bytes=0`。

因此，T01 判定为通过。

### 4.5 日志解释

- `201` 表示后端成功接收状态，不代表执行器产生了机械动作。
- `M0=0%`、`M1=0%`、`M2=0%` 是固件输出的控制状态，不是电流或位置传感器反馈。
- `Status [90, 90, 90, 90]` 中前三个值对应 board 01 的三路舵机；第四个值是接口兼容字段，不对应物理舵机。
- 同一块板使用多个逻辑设备 ID 分别上报状态，不代表多块开发板同时在线。
- 本日志不能证明固件采用非阻塞架构。当前实现采用周期轮询，网络请求和部分初始化流程仍包含同步等待。

## 6. T03 故障保护测试

状态：**未捕获，当前不能作为验证证据。**

### 6.1 测试目的

验证后端或网络失联后，固件停止电机输出，并在通信恢复后等待新的有效命令。

### 6.2 安全条件

- 电机和推杆不接机械负载；
- 使用低功率进行测试；
- 操作人员能够直接切断动力电源；
- 不安装螺旋桨。

### 6.3 操作步骤

1. 下发较低的电机测试功率；
2. 确认串口记录目标功率及状态回传；
3. 停止后端服务或断开 Wi-Fi；
4. 记录安全停机日志；
5. 恢复网络和后端；
6. 确认设备不会自动恢复之前的运动命令。

### 6.4 验收标准

正常命令阶段应出现：

```text
maker-esp32-pro-dc-01 command mode=WEB, enabled=true, e-stop=false, M0 target=20%
```

失联阶段应出现：

```text
[WARN] M0 WiFi/backend lost -> safety stop immediately
maker-esp32-pro-dc-01 M0=0%
```

恢复阶段应出现等待新命令的状态：

```text
[INFO] M0 WiFi/backend recovered, waiting for new command
```

以上为验收参考格式，不是已捕获结果。
