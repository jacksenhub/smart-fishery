仓库采用 npm workspaces 将 monorepo 拆为四个子包：`apps/frontend`（Next.js 16 + React 19 + Three.js/Recharts/TensorFlow.js 可视化仪表盘）、`apps/backend`（Express 4 API 服务，通过 UDP 广播在 42110 端口实现 ESP32 设备发现，并暴露 `/api/snapshot`、`/api/data`、`/api/servos`、`/api/propulsion`、`/api/twin/simulate`、`/api/ai/report` 等 REST 接口）、`apps/desktop`（Electron 43 主进程 `main.cjs`，按 `desktop-manifest.json` 启动前后端 Node 子进程并加载本地 3000/5000 端口页面）、`packages/shared`（纯 TypeScript 类型库，集中定义 WaterData、PlatformSnapshot、ServoDevice、PropulsionDevice、TwinSimulationResult 等跨端共享契约）。依赖方向严格单向：frontend → backend HTTP；desktop → frontend+backend 本地进程；firmware/esp32/* 各 Arduino 工程通过 WiFi 向后端 POST `/api/data`、`/api/gps/status`、`/api/servos/status`、`/api/propulsion/status` 并轮询 `/api/device/commands`。后端内部以内存 store（gps-store、servo-store、propulsion-store）+ `persistence.ts` 定时写入 `data/platform-state.json` 实现状态持久化，并通过 `twin-simulator.ts`、`ai-service.ts`、`mock-data.ts` 解耦仿真与演示数据生成。顶层 `package.json` 通过 `concurrently` 统一编排 dev/start/build/test/typecheck，并使用 electron-builder 将产物打包为 NSIS 安装程序输出到 `release/`。
