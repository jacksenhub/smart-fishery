## 1. 整体方案
本项目采用“按子应用独立 .env + 固件头文件”的轻量级配置体系，没有引入统一的配置中心或 YAML/TOML 配置文件。后端 Express、前端 Next.js、Electron 桌面端和 ESP32 固件各自通过自身运行时机制加载配置，并通过 `UISYS_API_TOKEN` 在设备—后端—前端之间共享同一份令牌实现鉴权。

## 2. 关键文件与位置
- 后端：`apps/backend/.env`、`apps/backend/.env.example`、`apps/backend/src/index.ts`
- 前端：`apps/frontend/.env.example`、`apps/frontend/.env.local`、`apps/frontend/src/lib/api.ts`、`apps/frontend/next.config.mjs`
- 桌面端：`scripts/configure-device-secrets.ps1` 生成的 `%APPDATA%\SZNX\backend.env`
- 固件：各 `firmware/esp32/*/wifi_secrets.{h,example.h}`
- 统一初始化脚本：`scripts/configure-device-secrets.ps1`

## 3. 架构与加载流程
### 3.1 后端（Node/Express）
- 启动时调用 `dotenv.config()` 加载 `apps/backend/.env`。
- 所有运行期参数均从 `process.env` 读取，并在入口处做类型校验与边界检查：
  - `PORT`、`UISYS_DISCOVERY_PORT` 必须为 1–65535 整数，否则抛错退出；
  - `CORS_ORIGIN` 以逗号分隔解析为允许来源集合，未配置时回退到 `http://localhost:3000` 与 `http://127.0.0.1:3000`；
  - `UISYS_DEMO_WATER_FEED`、`UISYS_DEMO_WATER_INTERVAL_MS`、`UISYS_SENSOR_FRESHNESS_MS` 控制演示数据注入与传感器新鲜度判定；
  - `DEEPSEEK_*` 系列环境变量驱动 AI 报告生成服务。
- 非本地回环地址访问写接口时，要求请求头 `x-uisys-token` 与 `UISYS_API_TOKEN` 进行 `timingSafeEqual` 比较，未配置 token 时直接返回 HTTP 503。
- UDP 发现端口 `UISYS_DISCOVERY_PORT`（默认 42110）用于局域网设备发现，监听后周期性广播 `UISYS_BACKEND_V1|<port>`。

### 3.2 前端（Next.js）
- 仅 `NEXT_PUBLIC_` 前缀的环境变量会被编译进浏览器代码，由 `src/lib/api.ts` 读取：
  - `NEXT_PUBLIC_API_BASE`：后端 API 基址，默认 `http://localhost:5000`；
  - `NEXT_PUBLIC_UISYS_API_TOKEN`：浏览器发起写请求时自动附加 `X-UISYS-Token` 请求头；
  - `NEXT_PUBLIC_FISH_VISION_MODEL_URL`：可选的 YOLO/ONNX 模型 URL。
- `next.config.mjs` 仅包含构建期配置（输出目录、standalone 模式、transpilePackages），不包含运行时配置加载逻辑。

### 3.3 桌面端（Electron）
- 通过 PowerShell 脚本 `configure-device-secrets.ps1` 将相同 token 写入用户目录 `%APPDATA%\SZNX\backend.env`，供 Electron 内嵌后端进程加载。

### 3.4 固件（ESP32）
- 每个固件工程提供 `wifi_secrets.example.h` 模板，包含 `WIFI_SSID`、`WIFI_PASSWORD`、`UISYS_API_TOKEN` 三个 C++ `inline constexpr char[]` 常量。
- 实际编译产物 `wifi_secrets.h` 由部署脚本批量覆盖，四个固件路径均被纳入脚本扫描范围。

## 4. 集中式初始化脚本（单点编排）
`scripts/configure-device-secrets.ps1` 是仓库中唯一的“配置编排入口”，负责：
- 交互式输入 SSID 与 Wi-Fi 密码（密码以 SecureString 输入，避免明文落盘）；
- 检测现有 `apps/backend/.env` 中的 `UISYS_API_TOKEN`，若长度不足 32 或显式指定 `-RotateToken`，则用 `RandomNumberGenerator` 生成新的 32 字节十六进制 token；
- 使用正则替换或追加方式写入 `HOST`、`PORT`、`UISYS_API_TOKEN`、`CORS_ORIGIN` 四项必需键；
- 创建 `%APPDATA%\SZNX\backend.env` 并写入相同的四键值；
- 对四个固件工程的 `wifi_secrets.h` 生成带转义后的 C++ 字符串字面量；
- 写入时使用 UTF-8 无 BOM 编码，避免 Windows 下编码问题。

## 5. 约定与约束
- **敏感信息不入库**：`.env`、`.env.local`、`wifi_secrets.h` 均未提交到版本库，仅 `.env.example` 和各固件的 `*.example.h` 作为模板保留。
- **跨端 Token 一致性**：后端 `UISYS_API_TOKEN`、前端 `NEXT_PUBLIC_UISYS_API_TOKEN`、固件 `wifi_secrets.h` 中的 `UISYS_API_TOKEN` 必须保持一致，否则 LAN 控制会被拒绝。
- **端口与发现端口固定**：后端 HTTP 默认 5000，UDP 发现默认 42110，客户端探测端口集合硬编码为 `[42111, 42112, 42113, 42114]`。
- **CORS 白名单策略**：未配置 `CORS_ORIGIN` 时只允许本机访问；生产环境需显式设置。
- **数值型配置强制校验**：`PORT`、`UISYS_DISCOVERY_PORT` 等端口类配置在启动阶段即校验范围，非法值直接抛错终止进程。
- **AI 外部依赖可插拔**：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TIMEOUT_SECONDS` 均为可选环境变量，缺失时 AI 功能不可用但不影响核心 API。
- **演示数据开关**：`UISYS_DEMO_WATER_FEED=false` 为默认关闭，仅在开发调试时开启；一旦收到真实传感器数据即自动停止注入。
- **持久化状态与配置分离**：平台运行态数据（水质历史、电池、AI 报告、系统日志）持久化到 `data/platform-state.json`，与环境配置完全解耦。

## 6. 适用边界
该配置体系适用于本仓库的四类组件：Node 后端、Next.js 前端、Electron 桌面端、ESP32 固件。它不是通用配置框架，而是围绕 `.env` + 头文件 + PowerShell 编排脚本的最小可行方案，适合单机/局域网无人渔船场景下的快速部署与调试。
